# Ghost in the Machine: Shot List and Production Brief

2026-10-17 · Albert Armea

## Overview

"Ghost in the Machine" is a glossy, code-animated pop music video that is deliberately the statistical average of the AI-made songs about AI it belongs to. It plays straight except in its bridge, where it notices it is a collage of the genre, then snaps back to the hook. Suno placed the bridge twice, so the video glitches briefly after the first verse and fully freezes after the second. The visual thesis: the whole genre is one set of defaults with a different random seed.

**Genre references** (alluded to, never copied): LGTM, Run It Again, The End of the Show, Not My Fault, Accept All. All are fully AI-generated, very poppy, with code-driven animation (an agent writing JavaScript or driving Blender), not a video-generation model.

**Deliverables**

- Main video, 16:9, 1080p (frame rate set by the style spec), with the final track
- 9:16 vertical cut of the bridge through the ending (section 7)
- Burned-in captions plus a separate SRT file
- Thumbnail
- The complete production log and every intermediate asset (section 2)

## Production rules

Everything is AI-generated by default. A human touches the work only for the narrow fixes listed below, and every such touch is logged.

**AI does:** the music (Suno v6), the style spec, the timing map draft, all animation code, renders, compositing, captions, the thumbnail and the edit.

**A human may only:**

- Approve or reject a take, render or plan (choosing, not editing)
- Correct A/V sync: caption timing, cut points, timing-map errors
- Fix technical failures the agent cannot (crashed render, broken install, an export setting)
- Run Suno's interface when the agent has no access to it (this is how the track was made)

A human never rewrites lyrics, redraws an asset or adjusts a creative choice by hand. If something is wrong creatively, the human says so in words and the agent makes the change, and both the instruction and the change go in the log.

**Logging (required, from the first action):**

- `log/production_log.md`: append-only, one entry per action. Each entry has a timestamp, the step (shot list ID where relevant), what was done, the exact command, prompt or script path, the output file paths, and why.
- `log/human_interventions.md`: every human action, with timestamp, what was done, why, and which rule above allows it. Anything that doesn't fit a rule is logged as an exception.
- `log/prompts/`: every prompt sent to Suno or any other model, verbatim, with its outputs.
- Never delete or overwrite an asset. Rejected takes, failed renders and superseded scripts move to `archive/` with a note in the log.
- Use git for all code and text, with one commit per logged step.

All of this, plus this document and the chat that produced it, will be published as the making-of record. Git holds code, scripts, logs and text. Large files (final renders, WAVs and stems, Suno takes, reference stills, .blend files, Claude Code session transcripts) are excluded from git, listed in a committed SHA-256 manifest, and published as a torrent seeded from a VPS with an HTTP web seed, mirrored to the Internet Archive. Frame sequences, Blender caches, tool caches, model weights, venvs and node_modules are never archived; log their versions and the commands that regenerate them instead. The inspiration videos are never published; link to them. Before the first commit, set up `.gitignore` and a pre-commit check that rejects any file over 50 MiB.

## Pre-production

The agent completes these in order; each ends at a review checkpoint (section 8).

1. **Extract the style spec.** For each inspiration video, pull stills with ffmpeg (one per scene change, plus one every 5 s) into `reference/stills/`. Write `style/style_spec.md` covering: palette as hex values, typography (find the closest OFL font for each), camera moves, transitions, easing, lighting, recurring objects and characters, caption style, pacing (average shot length), aspect ratio and frame rate. Then write the *average*: the single palette, font, camera vocabulary and character that best represents all five. That average is the look of this video. Don't copy any specific frame, character design or asset.
2. **Log the track.** Done before the agent started: a human generated it in Suno v6 with the submitted lyrics from section 5. The agent's first task is to log this retroactively: take ID, style prompt, settings, the chosen take and any rejected takes the human supplies, in `log/prompts/`, plus Suno's changes from section 5 in the production log, and the two lyric exceptions in `human_interventions.md`.
3. **Build the timing map.** Beat tracking (librosa) and word-level forced alignment (WhisperX or similar) against the as-sung lyrics produce `timing/timing_map.json`: section boundaries, beats, bars, the Bridge 2 dropout and the final chorus's return, and every word's start and end. A human checks it by ear; corrections go in the intervention log.
4. **Fix the seeds.** Every random process reads its seed from one config file. The main video uses seed 41; the bridge's second run uses 42; the restart at the end uses 43. Confirm that re-running a seed reproduces its frames exactly.
5. **Choose the pipeline per scene.** Blender (Python, Eevee) for 3D scenes; JavaScript canvas captured by Puppeteer for UI overlays; ffmpeg to composite. Record the choice per shot in `shots/pipeline.md`.

## Lyrics

Three versions exist, and each step between them goes in the log:

1. **Drafted:** Claude, in the planning chat.
2. **Submitted:** a human merged several of those drafts and pasted the result into Suno v6, after reverting the chorus's "Regenerate, regenerate" line because it didn't flow. Both are human edits to lyrics, which the production rules otherwise forbid, so both are logged as exceptions in `human_interventions.md`.
3. **As sung:** Suno changed the lyrics and structure during generation (verified by listening). This is the source of truth for captions, forced alignment and the shot list.

**What Suno changed:** it dropped the third bridge (the quietest, most self-aware one, with "The hook, the lights, the open door"), cut the third chorus to four lines with "Every song just sounds the same", and dropped the key change from the final chorus. In other words, the generator removed the song's most self-aware moments and its one structural surprise. Log these as AI changes, not human ones; they are evidence for the video's thesis.

**As sung:** see `lyrics/as_sung.txt`.

**As submitted to Suno:** see `log/prompts/suno/lyrics_submitted.txt`.

## Shot list

Twenty-three shots in the as-sung order (section 5), anchored to lyric lines rather than clock times; exact frames come from the timing map. "Robot" and "neon grid" are placeholders for whatever the style spec's average character and setting turn out to be. Overlays persist throughout: the credit `Ghost in the Machine – Claude Opus 5.5 music video v1.0` (top left, version ticking up each section), `seed: 41` and an FPS counter at 60 (bottom corners).

Suno placed the bridge twice, so the reveal happens twice: a brief glitch after Verse 1 that the video immediately covers up, and the full freeze after Verse 2. The second time, the video notices it is repeating itself.

## Review checkpoints and open items

The agent stops at each checkpoint and waits for approval. Approvals and rejections are logged as human interventions (choosing, not editing).

- [ ] **C1 Style spec:** `style_spec.md` plus a contact sheet of reference stills beside a test frame in the averaged style
- [ ] **C2 Track:** done (Suno v6, generated and chosen by a human); agent logs it retroactively
- [ ] **C3 Timing map:** a low-res preview with captions and beat flashes only; human checks sync by ear
- [ ] **C4 Animatic:** every shot as a rough low-res render at final timing; human approves the cut
- [ ] **C5 Per-section renders:** full quality, one section at a time, with a contact sheet of stills at each shot's anchor
- [ ] **C6 Final:** main video, vertical cut, captions, thumbnail, and a log audit confirming every asset in the project appears in the log
